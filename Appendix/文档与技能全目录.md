# 文档与技能全目录

这是对 DeepSeek Harness 仓库里两处"元资料"的完整测绘：`.agents/skills/`（打包给 agent 的操作说明书）与 `docs/`（开发者文档）。目的只有一个——**把"有哪些技能、docs 每个目录讲什么、每篇文档讲什么"一次说清**，作为正文各章的索引与对照层。（注：`.claude/` 里是一个符号链接 `skills → ../.agents/skills`——让按 Claude Code 约定去找 `.claude/skills` 的工具复用同一批技能；`.agents/` 有 `notes/` 与 `skills/` 两棵子树，`notes/` 的方法论见第 20 章、决策志见第 34 章。）

以下描述均由通读一手文件的开头/摘要得出，可核对到 `文件:行号`；正文已引用过的部分标注了去向。

## 一、`.agents/skills/` · 11 个技能

`.agents/skills/` 是 dsh 打包给 agent 的一套可复用"操作说明书"：每个技能是一个目录，核心是 `SKILL.md`——开头 frontmatter 的 `name`/`description` 决定它在什么场景被触发，正文是该场景下的工作流、铁律与产物约束（部分技能带 `references/`、`scripts/` 支撑文件）。它们统一遵循"guidance, not a checklist"的定位，把真正的权威（`AGENTS.md`、`docs/`、Agent Notes、各类 `verify-*` 门禁）当 source-of-truth 去链接，而非重复。详见第 32、33 章。

| 技能 | 触发时机 | 做什么 |
|---|---|---|
| **dsh-code-review** | 评审本仓 PR | 评审向导：先跑 `change-scope`，按 6 条阻塞项 + 一批人工检查（接口契约、生命周期/并发、能力边界、模型视角、invariant）审查，正确性优先于风格；是其他技能的调度中枢 |
| **dsh-prose-standard** | 写/审仓内一切散文（含注释/JSDoc/prompt/诊断串） | 编辑判断与必需覆盖的权威：先保全每条命题（actor/条件/时序/模态/负向保证）再删推理转录与冗饰；管制 `contract`/`boundary`/`shape` 等词、禁比喻；`vendor/` 与 archived note 恒排除 |
| **dsh-doc-standards** | 写/审文档、选层级详略、应对 `verify-doc-budgets` 红 | 文档标准落地：先审结构（定位、详略、教程 vs 参考）再审 slop（用最便宜探针查泄漏/重复/手写目录），按"搬家→精简→抬上限"应对超预算 |
| **dsh-trim-cot-leakage** | 清理读起来像"泄漏推理转录"的散文 | 用"HEAD 读者能否解析每处引用、验证每条断言"判定泄漏；给出 8 类泄漏分类与"不算泄漏"的保留项（issue 引用、对已合并 PR 的引证、抑制理由），先重述事实再删转录 |
| **dsh-translate-docs** | 用户**显式点名**（`disable-model-invocation: true`） | 扩展双语工作流：更新走 briefing 驱动的最小改、新配对走整篇翻译；术语表双向绑定、代码块逐字节一致，最后 `verify-translation-pairing --write` 记录一致性 |
| **dsh-doc-site-sync** | 发布/移动/删 VitePress 站点页、改 `website/docs.ts` 映射 | 把仓库 Markdown 当唯一可编辑源、网站是"被测投影"；按字段填 `DocsPage` manifest、维持链接投影规则，跑 `docs:check`/`doc-sync`；禁手改 `.generated/`，同步不等于部署 |
| **dsh-find-simplifications** | 找非显然的简化点、写简化 Agent Note/TODO | 把"找可简化处"变证据驱动的 note：按强候选标准（无生产消费者、双表示镜像、投机通用性、手写造轮子等）广度扫描、逐个证伪；双 LLM 适配器/双持久化后端默认视为有意、不可删 |
| **dsh-merging-stacked-prs** | 落地依赖式 PR 栈 A←B←C | 强制用 GitHub 官方 stack 对象 + `gh stack merge` 落栈，禁手动逐个 merge/retarget；校验 native 支持→连接缺失成员→按需 rebase/merge-forward→预检范围→验证 MERGED 后再删分支 |
| **dsh-pre-push-checks** | push/force-push/标 ready、或 `gh stack sync` 后 | 选"覆盖本次 diff 的最小测试与检查"而非反射式跑全套：先 `change-scope` 看范围、按 surface 选证据；管 force-push 的 lease 保护与 post-sync 验证 |
| **dsh-archive-agent-notes** | 增删/审计/归档/恢复 Agent Notes | 按"未来价值"而非字数/年龄分类：已实现且仍指导决策的留 active，已完结的按冻结三元组搬到 `archived/{kind}`，被拒且不再防错的整组删除；新增 note 时做 supersession 审计 |
| **record-browser-gif** | 录浏览器/Web UI 演示 GIF（GUI PR 必附） | 用真实 server+真实 API+真实模型轮次录 3–6 个语义状态帧、确定性编码成 GIF；录制与发布分离，发布只推到专用 orphan assets 分支并用 `?raw=true` 嵌入 PR body，绝不提交进 PR 自身分支 |

**三个核心技能展开：**

- **dsh-code-review** 是评审总入口与调度中枢：明确"是向导不是清单"，先核实 PR 真实 base/head 并跑 `change-scope`；6 条阻塞项里第 1 条把"新增散文的语义评审"外包给 `dsh-prose-standard`、双语引到 `dsh-translate-docs`、测试门禁引到 quality-gates note，自身聚焦"代码之外看不到的东西"——接口两侧契约、竞态/取消/释放、能力与消费者匹配、模型收到的确切 prompt/schema、invariant 的生命周期与负向控制。
- **dsh-prose-standard** 是全仓散文的编辑权威，被多个技能引为"complete-proposition 规则"的所有者：铁律是"先写够以保全契约，再删推理转录、重复与装饰"，按 prose 位置（公共 JSDoc/内部注释/README/Agent Note/prompt/诊断）分别规定必需覆盖。
- **dsh-find-simplifications** 把模糊的"找简化"收敛为证据驱动产物：先读 `AGENTS.md` 与既有 note 理解"有意为之的架构"，再按强/薄候选清单广度扫描、用 `rg` + 读调用点逐个证伪，最后写结构化 proposed note 或内联 TODO；与 `dsh-archive-agent-notes` 协作处理被取代的 note。

## 二、`docs/subsystems/` · 45 个子系统参考

"一子系统一页"的参考册：每页讲清该子系统搬运的**数据结构**，并在有 `ctx` 服务/事件作用域处附上生成的 Cordis API（服务与事件词汇）。它与讲跨子系统*行为*的 `architecture.md` 互补。正文 Part II（第 05–18 章）已覆盖其中约 25 个；下表按主题分组给全部 45 个。

### 会话与持久化家族
- **session** ｜ `ctx.sessions` / `SessionEventMap`、`deriveMessages()` ｜ 内存中事件溯源的只读追加日志，一次交互的唯一真相源；LLM 历史由日志派生而非另存（第 07 章）。
- **persistence** ｜ `ctx.sessionPersistence` / `SessionHeader`、`session/flush` ｜ 事件日志耐久层：JSONL+SQLite 双后端、flush 检查点、崩溃后合成 `turn/end` 修复（第 17 章）。
- **session-query** ｜ `SessionRecord`、`SessionEventSurface` ｜ 对"活会话优先"逻辑语料做精确读取、关系追踪、语义过滤与全文检索（第 17 章）。
- **session-projection** ｜ `ctx.sessionProjections` / `ProjectionDefinition` ｜ 域插件把日志派生的每会话状态折叠成整值推给客户端；框架驱动、域只算数学。
- **session-telemetry** ｜ `ctx.sessionTelemetry` ｜ 出站会话上报能力缝：捕获点、脱敏瀑布、交接游标，边界止于 `emit()`，重试交给 OTel SDK。
- **session-title** ｜ `foldSessionTitle()` ｜ 最新胜出的耐久标题状态与可选异步标题提供者词汇。
- **session-reference** ｜ canonical URI ｜ 结构化的跨会话引用请求与预备消息上下文，替代把 UI mention 语法塞进 agent core。
- **compaction** ｜ `ctx.compaction` / `compaction/start|summary|end` ｜ 可选压缩缝：带锁摘要压缩，摘要经一条 `user/message` replace 落到 surface（第 16 章）。
- **storage** ｜ `ctx.storage`、`ctx.storageDomain` ｜ 持久化一切非会话日志之物：hub 不做 IO，后端管介质、数据形态管语义。
- **spill** ｜ `ctx.spillStore` ｜ 把工具超大文本落盘，返回面向模型的定位符与取回提示（第 16 章）。

### 执行世界
- **shell** ｜ `ctx.shell` / `ShellExecRequest` ｜ bash 执行缝，`resolve()` 把模型请求补全为已解析规格（第 12 章）。
- **subprocess** ｜ `ctx.subprocess` / `DshEnvironment` ｜ 底层进程组机制：托管 `DSH_*` 环境、凭据擦洗、采集输出，被 shell/LSP/PTY/ACP 复用（第 12 章）。
- **terminal** ｜ `ctx.terminals` ｜ 持久 PTY 会话词汇，区分"送出为何返回"与"顶层 shell 是否存活"（第 12 章）。
- **sandbox** ｜ `ctx.sandbox` / `SandboxMode` ｜ 给同世界子进程 argv 包一层文件效果策略，后端跨平台（第 13 章）。
- **code-runtime** ｜ `ctx.codeRuntime` ｜ 可选代码执行缝：跑模型写的程序、对接宿主异步绑定（第 14 章）。
- **filesystem** ｜ `ctx.fs` / `FsTarget` ｜ 可选文件缝：原子读写编辑 + 观察策略（先读后写）（第 14 章）。
- **lsp** ｜ `ctx.lsp` / `LspOperation`（四种语义查询） ｜ 语义代码导航能力缝，闭合 union，换 provider 不改模型请求（第 14 章）。

### 模型与提示
- **llm-streaming** ｜ `ctx.llm` / `Message`、`StreamChunk`、`LlmAdapter` ｜ 对话与流式类型：内容块联合、装配后的模型请求、线协议与适配器契约（第 10 章）。
- **system-prompt** ｜ `ctx.systemPrompt` / `AssembleContext` ｜ 提示贡献者与一次装配调用间交换的数据（第 08 章）。
- **tools** ｜ `ctx.tools` / `ToolDefinition` ｜ 工具流水线：schema DSL、受守护执行、UI 呈现类型，allowlist 防内部字段泄漏进模型请求（第 09 章）。
- **token-meter** ｜ `TokenMeasurement` ｜ 一个脱离态的重放快照，度量请求压力与 surface 定位定价。

### 编排
- **subagent** ｜ `ctx.subagents` / `SubagentError` ｜ 委派子 agent 的缝，多 provider 按名共存，含可续对话编排与后代发现（第 15 章）。
- **workflow** ｜ `ctx.workflowEngine` ｜ 让 agent 跑模型写的编排脚本启子 agent，单引擎、无命名注册表（第 15 章）。
- **plan** ｜ `ctx.planMode` / `plan/mode`、`foldPlanMode()` ｜ 每 agent 的计划模式协作状态（软引导），贡献 `plan:policy` 段与 `exit_plan_mode` 工具（第 15 章）。
- **jobs** ｜ `ctx.jobs` / `JobId`、`JobStatus` ｜ 长运行工具的后台任务运行时，靠属主授权而非 id 保密做访问控制（第 15 章）。
- **schedule** ｜ `ScheduleId`、`After/At/Every` ｜ 会话本地的耐久提醒，到点作为普通对话轮回到原活会话。
- **goal** ｜ `GoalId`/`GoalRef` ｜ 事件溯源的同会话目标：身份、激活、变更记录与轮次归属。

### 交互与前端
- **web** ｜ `ctx.web` / `WebFetchProvider` ｜ 一服务两操作（搜索+抓取）的联网能力缝。
- **web-server** ｜ `ctx.webServer` / `WebRoute` ｜ GUI 宿主的浏览器 HTTP 载体，命名路由 + index 变换 + 单一 fallback，本身不懂 harness 概念（第 17 章）。
- **user-questions** ｜ `ctx.userQuestions` ｜ provider 中立词汇：工具/权限插件需人先回答才能继续时用。
- **commands** ｜ `ctx.commands` ｜ 人类命令注册表：交互适配器发现并直接执行插件命令，不产生模型消息。
- **feedback** ｜ `MessageFeedbackRating` ｜ 单条助手消息的可编辑反馈，本地存储 sidecar，与不可变的 `feedback/record` 事件分离。
- **client-modules** ｜ `ctx.clientModules` / `window.__DSH_BOOT__` ｜ Web 插件表：扫描声明 `dsh.client` 的包、组装 boot 图并按 `/plugins/<id>/client.js` 供包。

### 能力与治理
- **skills** ｜ `ctx.skills` / `skills/change` ｜ 技能注册表（host + 每作用域分层），合并 provider 目录、暴露 `skill` 工具（第 16 章）。
- **extensions** ｜ `ctx.cordisInspect` 等 ｜ 让 agent 定义带版本的 Cordis 包、跑其宿主/浏览器两半，并在写码前查已批准的运行时元数据（第 18 章）。
- **attachment** ｜ `ctx.attachments` / `ImageAttachmentRef` ｜ 把二进制图像所有权与会话日志分离，对象耐久后才发布内容寻址引用（决不放 base64/URL）（第 17 章 §八）。
- **settings** ｜ `ctx.settings` / `SettingsNamespace` ｜ 用户设置缝：一份用户文档按命名空间分节，按"默认→base→用户段"分层解析并热提交（第 17 章 §九）。
- **credentials** ｜ `ctx.credentials` / `CredentialRef` ｜ 凭据缝：配置只带引用（环境变量名），每次操作解析一次、轮换即刻生效（第 13 章 §八）。
- **approval** ｜ `ctx.approval` / `ApprovalOutcome` ｜ "此动作可否放行"的用户批准缝，闭合且失败即拒，只有 `allowed-once` 才放行（第 13 章 §八）。
- **permission-presets** ｜ `ctx.permissionPresets` / `PresetSpec` ｜ 把 sandbox 模式与 approval 策略两旋钮打包成命名预设，本身不做执行、只写穿各旋钮（第 13 章 §八）。
- **scope** ｜ `ScopeKey`、`Scoped<T>`（库原语，非服务） ｜ 提供作用域注册的身份、载体与分层词汇，让一个注册上下文兼表每 agent 可见性与共享生命期。
- **workspace** ｜ `ctx.workspaceRegistry` / `WorkspaceId` ｜ 用户所在目录的持久记录（稳定 id + 标题 + 会话顺序），存于 storage domain，对模型不可见。
- **core** ｜ `ctx.agents`/`ctx.agentLoop` / `Agent`、`AgentHandle` ｜ `packages/core` 如何驱动 agent 循环：六包一 turn 的主干、agent 创建与所有权、全仓类型模式（第 05/06 章）。
- **invariants** ｜ `ctx.invariants` ｜ 包自持运行时不变式检查的可配注册表，管选择、命名保留、子 fiber 生命期与按包归因的失败（第 30 章）。

### 远程调用
- **typert** ｜ `TypertLookupMap`/`TypertContextMap` ｜ 生成的 Remote 制品、Host Gateway 与消费者 API 装配共享的类型，划定 Host Gateway/Client API 边界（第 17 章）。

## 三、`docs/` 子目录与顶层文档

`docs/` 整体分六层：**架构总纲**（`architecture.md` + 图集/术语/能力缝）统领；**子系统参考**（上节 `subsystems/`）逐包深潜；**Cordis 教程与 API**（`cordis-primer` + `cordis-tutorial/` + `cordis-api/`）自底层框架讲起；**面向用户与插件作者的 `user/`**；**贡献者流程**（`cookbook/`、`i18n/`、`postmortem/`）；以及**大目录 catalog**（`config-catalog`、`tool-catalog`、`persistence-catalog` 等生成式全量清单）。除生成文件外几乎每篇都 `English | 中文` 双语配对。
