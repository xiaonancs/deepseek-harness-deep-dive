# 版本更新追踪 · rc.5 → rc.7（2026-08-13 → 2026-08-17）

本研究正文以 **rc.5**（commit `47f9438`、2026-08-13、12,293 commits）为一手源码基线。此后官方在四天内连发两个候选版（release candidate，候选发布版）。本页记录这段增量里与本报告相关的更新，逐条给出 `文件:行号` 或对应 ADR（Architecture Decision Record，架构决策记录），并说明验证方式，方便读者把正文快照与最新代码对上。

**核对口径**：对 `deepseek-ai/deepseek-harness` 的 master 分支执行 `git fetch` 后，新 HEAD 为 `99f6f02fec`（2026-08-17、**12,404 commits**），相对旧基线新增 **111 个 commit**（其中 30 个 `fix`、14 个 `docs`、9 个 `feat`、7 个 `test`，其余为合并/发布/持续集成）。以下每条都在该新 HEAD 上直接读源码核实（`[verified]`）。

## 一、版本与规模

- **两次发布**：`release/dsh-0.1.0-rc.6`（PR #2531）与 `release/dsh-0.1.0-rc.7`（PR #2620）先后合并；根 `package.json` 的 `version` 现为 **`0.1.0-rc.7`**，并新增 git 标签 `dsh-v0.1.0-rc.7`。主版本仍是 0，预览姿态不变。
- **包数不变**：仍是 **219 个** `@deepseek-ai/dsh-*` workspace 包。窗口内有人尝试"精简包数"（PR #2571 `worktree-reducepkg`），但**随即被回退**（PR #2577），本窗口 `packages/*/*/package.json` 的新增/删除净为零 `[verified]`（`git diff --diff-filter=AD 47f9438..HEAD`）。
- 因此正文里"约 219 包、主版本 0、开发者预览"这些结论在 rc.7 仍成立；变化主要在**行为与打包**层面，下面分述。

## 二、LLM 适配器：DeepSeek 新增"低推理档"（对应 Ch10）

DeepSeek 适配器的推理力度（reasoning effort）枚举从 `off / high / max` **扩为 `off / low / high / max`**，新增了介于"关闭"与"高"之间的 `low` 档 `[verified]`（`packages/llm/llm-deepseek/src/index.ts:70,95`；`adapter.ts:96` 定义 `LOW_REASONING_EFFORT = ReasoningEffortId('low')`；`serialize.ts:26-49` 补齐序列化分支）。这与 Ch10"reasoning 是一等公民、力度由适配器自己声明"的判断一致——它落在 ADR `2026-07-24-adapter-owned-reasoning-effort-capabilities` 所说的"适配器自有推理力度能力"框架内（PR #2549）。同窗口还有一处 DeepSeek `maxToken` 一致性修正（PR #2596）。

## 三、编排与委派：后台一次性子代理（对应 Ch15）

新增 ADR `2026-08-12-product-subagent-one-shot-background-tasks`，让 **Codex 与 Claude Code 两个子代理后端能作为"后台一次性任务"运行**（`feat(agent-presets)`，PR #2374）；配套更新了 `2026-08-04-claude-code-and-codex-subagent-backends` 与 `2026-08-10-fork-children-stay-one-shot`（fork 出来的子代理仍保持 one-shot 语义）。这是 Ch15"子代理六个 provider、one-shot vs continuable"叙述的直接延伸：此前 Codex/Claude Code 后端偏同步一次性，现在可把它们排到后台跑。

## 四、多模态：图像附件与 ACP 图像桥（对应 Ch17、呼应 Ch18）

富内容桥（rich-content bridge，PR #2252 / issue #1463）在本窗口并入 master，带来两条与本报告相关的能力：

- **有序图像批次准入**：`feat(attachment): add ordered image batch admission`（commit `219d2a1fb9`），配套 ADR `…multimodal-image-input-and-durable-attachments` 与子系统文档 `docs/subsystems/attachment.md` —— 图像作为**可持久化附件**按有序批次进入会话。
- **ACP 图像桥**：`feat(acp): bridge durable image prompts and replies`（commit `4f87c1fe6d`，作者 Tianyi Cui），更新 ADR `2026-07-23-acp-automation-only-protocol` —— 让"仅自动化"的 ACP（Agent Client Protocol，智能体客户端协议）通道也能收发持久化图像提示与回复。

说明：承载它的 `packages/attachment`（`ctx` 上的附件接缝）与 `ui-attachment` 在 rc.5 就已存在，本窗口的增量是**把图像打通到"提示/回复"与 ACP 两条链路**。这也给 Ch18 那条"MCP（Model Context Protocol，模型上下文协议）把非文本内容降级为占位符"的局限提供了对照——图像在 dsh 内部本就有一条经附件子系统的一等通路，MCP 侧的降级是该协议消费面尚未接上，而非引擎不支持图像。

## 五、打包与供应链：install-face 瘦身（对应 Ch19、Ch20）

rc.7 集中收敛了"装机面（install face，即用户 `npm install` 时真正会拉取/加载的那部分）"的体积与纪律，直接回应 Ch19 记录的"下载体积偏大 / npm 供应链"担忧：

- **拒绝在模块作用域静态加载可选依赖**：`feat(release): reject a module-scope load of an optional dependency`（commit `7b973e27c8`）—— 声明为 `optionalDependencies` 或 `peerDependenciesMeta.<name>.optional` 的依赖，若被"静态 import"就会被门禁拦下（静态 import 等于宣告它其实不可选，破坏"可缺席"承诺）。
- **把仅浏览器用的依赖挡在装机面之外**：`feat(scripts): gate browser-only dependencies out of the install face`（commit `6e77499326`）—— 沿每个包的 host 面与 browser 面行走，报告"任何 host 面都够不着的外部包"。
- 注：上面两道检查引入时各是独立脚本（`verify-optional-dependency-imports.ts` / `verify-client-runtime-deps`），随后**并入现存门禁 `scripts/verify-runtime-closure.ts`**；两个引入 commit 因仓库历史改写已非当前 HEAD 祖先（仅 `git show` 可达），故按其改写前对象引用。
- 配套：`perf(web): remove the module preload polyfill`（`ef249da2e9`）、发布顺序按依赖分区排序（PR #2546）、npm import 修正（PR #2529）。

换言之，Ch19 里"体积/供应链是阶段性局限"的判断，在 rc.7 已看到官方用**新门禁 + 装机面裁剪**主动缩小这块波及面——这也是 Ch20"面向 agent 的工程纪律靠门禁固化"的又一实例。

## 六、终端：node-pty 升级到 1.2-beta（对应 Ch12/Ch14）

`subprocess-local` 把 node-pty（伪终端 pseudo-terminal 的 Node 绑定）升到 1.2-beta（PR #2517），并为 manylinux 重新构建、给 python-runtime 增加预构建回退，同时修了一处"保持受控提示符、让持久 bash 更快就绪"（commit `a8dc6f9776`）。这属于 Ch12/Ch14 执行世界的底层依赖维护，机制结论不变。

## 七、其他（较小，或与本报告关系较弱）

- **插件自有设置面**：`feat(settings): serve every registered namespace and key plugin cards on it`（PR #2404）—— `ctx.settings` 接缝（rc.5 已有）之上补了一个"每个注册命名空间都出卡片"的图形界面设置面。
- **UI 预设改名**：agent 预设里的 "code preset" 更名为 **"PTC mode"**（PR #2559，`ui-agent-preset/src/client/locales.ts:40`），仅界面文案。
- **测试加固**：新增 `test/cordis-turn-end-diagnostic`（PR #2535）与 python SDK 的 `model-visible` 断言快照（PR #2462）—— 分别加固 Ch06 回合边界与 Ch07"模型可见 ⟺ 已记录"不变量。
- 其余多为修复：Safari 文本框重排、pwsh 终端浮层重复加载（PR #2417）、大历史分页（PR #1371）、cordis 工具样式（PR #2527）等。
