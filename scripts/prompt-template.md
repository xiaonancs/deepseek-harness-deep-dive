# 章节生成 Prompt 模板（所有章节共用规范）

你在为 DeepSeek Harness（`dsh`）源码写一份**中文深度技术解析**的其中一章。源码仓库在绝对路径：
`/Users/hexiaonan/workspace/publish/deepseek-harness/repo/deepseek-harness/`（下称 REPO）。

## 铁律
1. **源码实证**：所有机制性结论必须给 `文件:行号` 或对应 docs/ADR 路径。先 Read 你分到的 key_source_paths，再按需 Grep/Read 扩展。**不要臆造**路径或 API；拿不准就实际打开文件核对。
2. **证据等级**：结论按三档标注——`[verified]` 源码可证（给 file:line）· `[inferred]` 合理推断（有据但非直证）· `[claimed]` 仅社区/二手口径。承重结论若只有 `[claimed]` 必须弱化措辞。
3. **证据边界**：源码能证明**实现**，未必能证明**动机/语言选型/团队意图**。凡"为什么这样设计"类，用「可能/或许/不排除」，不下定论。
4. **定量优于定性**：给具体行数、文件数、包名、事件名、类型名。

## 七维分析框架（本章正文骨架，按此展开）
1. **本质是什么** — 该子系统的根本目的与在整体中的定位。
2. **核心问题与痛点** — 它要解决什么难题（放到 agent harness 语境）。
3. **解决思路与方案** — 架构 + 关键设计选择（**承重判断走 ratify-note，见下**）。
4. **实现细节关键点** — 关键代码路径、数据结构、事件、类型、不变量。
5. **易错点与注意事项** — 陷阱、边界条件、隐式依赖、门禁约束。
6. **竞品/横向对比** — 同类 harness（Claude Code/Codex/Pi）或通用做法怎么处理（**承重对比走 ratify-note**）。
7. **仍存在的问题与局限** — 设计局限、已知 deferred、改进空间（**承重缺陷判断走 ratify-note**）。

## ratify-note（承重判断的可信闸，维度 3/6/7 必用）
凡涉及"为什么这样设计/权衡了什么""竞品孰优""这是不是缺陷"的**承重结论**，不要直接断言，改用一个简短 ratify-note 块：

```
> **ratify-note · <判断主题>**
> - 候选解释：A … / B …（至少 2 个，含"沿用现状/什么都不做"作基线时更好）
> - 各自利弊：A 优…缺… / B 优…缺…（承重判断反面要列足）
> - 选定 & 理由：选 X，因为 …（第一性 + 源码/对标证据）
> - 证据等级：[verified|inferred|claimed]（附 file:line 或来源）
> - 残余风险 / pre-mortem：若半年后此判断被证伪，最可能因 …
```

## Mermaid 图（≥4 张，硬性规范）
- 每张图**必须**用白色背景板 div 包裹（暗色主题下黑字可读的底线）：
  ```
  <div style="background: #ffffff !important; background-color: #ffffff !important; padding: 16px; border-radius: 8px; margin: 16px 0;" bgcolor="#ffffff">
  <!-- mermaid 代码块放这里 -->
  </div>
  ```
- 图内 `%%{init: {'theme':'neutral'}}%%` 开头；灰黑色板，禁止彩色主题。
- 长宽比控制在 1:2 ~ 2:1；过扁折行、过高并列重排。
- **禁止**：裸泛型 `Foo<Bar>`（用 `Foo~Bar~` 或改写）、HTML 实体、节点文字里的特殊 Unicode/引号。节点文字尽量短。
- 每张图配一句图注说明它证明了什么。
- 图的类型建议：架构/依赖图、时序图（sequenceDiagram）、状态图、数据流图各取所需。

## 文风与结构
- 章节标题已给定（6-14 中文字），正文内部大标题短、稳、克制。
- 现状陈述（present tense），先事实再解释再判断；收敛"最精妙/必然选择/极致工程"这类过强措辞。
- 篇幅约 2500–4500 中文字（不含图代码）。
- 开头一句话点题（本章讲什么、读完能回答什么问题），结尾一段小结 + 与相邻章的衔接。
- 章末加 `## 源码索引` 列出本章引用的关键 file:line / docs / ADR，便于交叉核对。

## 输出
把整章写成一个 Markdown 文件，**直接用 Write 工具写到给定的目标绝对路径**。不要把正文回贴到对话里，只回一句"已写入 <路径>，字数约 N，含 M 张图、K 条 ratify-note"。
